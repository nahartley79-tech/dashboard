Rail-vs-wide for on-pacers is neutral (already in v12). "Swooper in hot pace" underperforms its rank — so no swooper bonus. Only the death seat is a real, v12-independent negative.
Why shadow, and not scored into v12

Tempting to add a v12 geometry term — but the evidence says no. The death seat bites almost entirely on low-v12 horses we don't bet (5 of ~785 live bets ever), so a v12 ranking penalty would only reshuffle non-contenders, and ranking nudges are zero-sum for top-3 catch — the same reason the ClassDrop ranking bonus was rejected. A live bet-fade is near-immaterial too. So it ships as an inert, flag-gated fade with a tracker, ready only if the profile ever starts costing us.

The gate

In v24_qualify, a live BET is faded to WATCH 'PaceGeometryFade' when _is_death_seat: pace = M, drawn in the outer third (barrier/field ≥ 0.66), into a hot pace (front_ct ≥ 4). Gated by PACEGEO_LIVE=False → inert. run_venue_v28 supplies front_ct / field_size; missing either = no-op.

Promotion rule (set in advance)
Flip PACEGEO_LIVE=True only when v_pacegeo_status shows ≥ 25 settled death-seat bets clearing below break-even. Expect a slow fill — the profile is rare. Verdict is inverted: we want these to lose; if they don't, the fade stays off.
Also shipped: the dashboard in-running map

The real payoff from the geometry work is visual. The Race Card now has three tabs per race — Table, Speed map · start (settle), and Speed map · running (projected formation in lines, rail→wide, death-seat runners flagged red, with the hot-pace swooper call). You read the geometry yourself and avoid the death seat, which is where this signal actually pays.
